Worksheet: start to finish

Given an IP and a mask (as /27 or 255.255.255.224), work it in this order:

  1. Mask both ways. /p means p ones. The first three octets are 255; the 4th octet gets p − 24 ones from the left. Add their place values (128, 64, 32 …) to get the octet. Going the other way, count the 1s.
  2. Binary mask. Write it as four groups of 8: 11111111.11111111.11111111.11100000 for /27.
  3. Increment = 256 − the 4th mask octet.
  4. Hosts per network = 2h − 2, where h = 32 − p (the 0s in the mask).
  5. Network chart. Start at .0 and count up by the increment. Each row’s broadcast is the next row’s network − 1. The useable range is network + 1 to broadcast − 1.
  6. Network and broadcast of the IP. Find the row the IP’s last octet falls in (round down to a multiple of the increment).
  7. Network, host or broadcast? First address of its row = network. Last address = broadcast. Anything between = useable host.
  8. Total networks = 2n, where n = p − the class default: Class A (first octet 1–126) /8, B (128–191) /16, C (192–223) /24. For 10.x.x.x/27: n = 27 − 8 = 19 → 524,288. Some classes count from /24 instead (n = p − 24); the game accepts either for the worksheet.

Work it top to bottom: everything above the chart comes from the mask, everything about the given IP comes straight off the chart, and total networks is a separate calculation from the IP’s class, so leave it for last.

VLSM: start to finish

VLSM (variable length subnet masking) splits one network, here a /24, into subnets of different sizes, each just big enough for its hosts.

  1. Biggest first. Assign the subnet that needs the most hosts first, starting at the .0 network, then the next biggest, and so on. Big blocks first keeps every subnet lined up on its own boundary.
  2. Host bits. For each subnet find the smallest h where 2h − 2 ≥ the hosts needed: h = 2 → 2 hosts, 3 → 6, 4 → 14, 5 → 30, 6 → 62, 7 → 126. Watch the edges: 15 hosts don’t fit in 14, so they need h = 5.
  3. Bit grid. Write h 0s on the right (host bits) and 1s in the rest (network bits).
  4. Mask. Add the place values above the 1s to get the last octet: 255.255.255.x.
  5. Block size = 2h, which is also 256 − the mask’s last octet.
  6. Network. The first subnet starts at .0. Each one after starts at the previous network + the previous block size, which is the same as the previous broadcast + 1.
  7. Broadcast = network + block size − 1. Useable range = network + 1 to broadcast − 1.
  8. The extra row is the network after the last subnet: its broadcast + 1. Everything from there on is still free.

Example: 192.168.0.0/24 with 58, 29, 15 and 7 hosts → h = 6, 5, 5, 4 → masks .192, .224, .224, .240 → networks .0, .64, .96, .128, and the next network is .144.

Packet Tracer subnetting lab

The “Subnetting Scenario” lab gives you a /24 and a topology of two routers, each with LANs (router port → switch → PC), joined by a serial WAN link.

  1. Subnets needed = the number of LANs + 1 for the R1–R2 link. Count networks, not devices.
  2. Bits to borrow: the smallest n where 2n ≥ subnets needed. That creates 2n subnets of 28−n − 2 usable hosts. If that’s fewer than the hosts each LAN needs, you borrowed too many.
  3. Binary of the subnets: the subnet number lives in the borrowed (leftmost) bits. With 3 borrowed bits, subnet 2 is 01000000 = .64.
  4. New mask: n 1s, then 0s, in the 4th octet. 3 borrowed bits = 11100000 = 255.255.255.224.
  5. Subnet table: subnets go up by the block size (256 ÷ 2n). First usable = subnet + 1, broadcast = next subnet − 1, last usable = broadcast − 1.
  6. Assign the subnets in order: R1’s LANs, then R2’s LANs, then the WAN link.
  7. Addressing Table rules: routers get the first usable address on their LANs; R1 gets the first and R2 the last usable on the WAN link; switches get the second usable; PCs get the last usable. A switch’s or PC’s default gateway is its router’s LAN address; routers have none (N/A).

Part 2, the IOS commands (configuring the router, switch and PC), is practiced in No Shutdown, the sister site for Cisco IOS commands.

Shortcuts to memorise

The mask ladder. The only values a mask octet can take, in order. Each step adds the next place value:

  • The same pattern repeats for /17–/23 (third octet) and /9–/15 (second octet): /18 is 255.255.192.0, just like /26 ends in 192.
  • Increment = the value of the last 1 bit in the mask = 256 − the mask octet. It halves each time the prefix goes up by 1.
  • Hosts = increment − 2 when the mask ends in the 4th octet. Otherwise 2h − 2.
  • Powers of 2: 2, 4, 8, 16, 32, 64, 128, 256, 512, 1,024. Anchors: 210 = 1,024 and 220 = 1,048,576; step up or down by doubling or halving.
  • Classes: A is 1–126 (/8), B starts at 128 (/16), C starts at 192 (/24). 128 and 192 are the first two steps of the mask ladder.
  • The chart: networks are multiples of the increment. Broadcast = next network − 1. First usable = network + 1. Last usable = broadcast − 1.
  • Network, host or broadcast? A multiple of the increment is a network; one less than a multiple is a broadcast; anything else is a host.
Subnet Chart — step by step

Use this for any "fill in the chart" question. Example: 172.16.62.68/26

  1. Turn the prefix into a mask. The prefix is how many 1s there are. Every 8 ones = 255. Leftover ones go in the next octet, adding from the left: 1→128, 2→192, 3→224, 4→240, 5→248, 6→252, 7→254.
    /26 = 8+8+8+2 → 255.255.255.192
  2. Copy the 255 octets. Wherever the mask is 255, the IP copies straight down into every answer. Find the interesting octet: the one that isn't 255 or 0. That's the only octet you work on.
    Answers all start 172.16.62. — only work on the .68
  3. Find the increment. Increment = 256 − interesting octet. (It's also the place value of the last 1 bit in the mask.)
    256 − 192 = 64
  4. List the subnets. Start at 0 and keep adding the increment. Stop before 256.
    0, 64, 128, 192
  5. Round down. Find the subnet your IP falls in: the one at or just below the IP's number.
    68 is past 64 but not at 128 → subnet .64
  6. Fill in the chart.
    BoxHowExample
    Networkthe rounded-down subnet.64
    Broadcastnext subnet − 1128−1 = .127
    Gatewaynetwork + 1.65
    Last usablebroadcast − 1.126
    Usable hosts2h − 2, h = 32 − prefix2⁶−2 = 62

Answer

Network 172.16.62.64 · Gateway .65 · Last usable .126 · Broadcast .127 · 62 hosts

Steps 3 and 4 do most of the work. Once you have the increment and the subnet list, the rest is just +1 and −1.

ANDing — finding the network address

Example: 10.103.166.35 with mask 255.255.255.252 (/30)

  1. Copy the 255 octets. Anything under a 255 copies straight down; anything under a 0 becomes 0.
    → 10.103.166.___
  2. Convert the interesting octet of both the IP and the mask to binary. (See "Binary" below.)
    35 = 00100011 · 252 = 11111100
  3. AND them column by column. The result is 1 only where both are 1. Anything over a 0 becomes 0. 
    IP    00100011  (35)
Mask  11111100  (252)
      --------
AND   00100000  (32)
  4. Convert back to decimal and put it in the blank.
    → 10.103.166.32

Shortcut to check your answer

Increment = 256 − 252 = 4. Subnets go …28, 32, 36… 35 rounds down to 32. ANDing and rounding down always give the same answer.
The "round down" rule

The network is always the subnet number at or below your IP: round down to the nearest multiple of the increment.

This works because each subnet runs from its own number up to just before the next one. With increment 4: .32 covers .32–.35 and .36 covers .36–.39, so .35 can only be in .32.

Lands exactly on a subnet number? Then that is the network. Nothing rounds down. That address is the network address itself, so a host can't use it.

Decimal → binary (subtract method):

  1. Start at 128.
  2. If your number is ≥ that place value, write 1 and subtract it. Otherwise write 0.
  3. Move to the next place value (64, 32, …) and repeat until you've done all 8.

Formulas
  1. Usable hosts per subnet = 2h − 2, where h = host bits = 32 − prefix. (You lose the network and broadcast addresses.)
    /27 → h = 5 → 32 − 2 = 30
  2. Number of subnets = 2n, where n = bits borrowed. The new prefix = old prefix + n.
    /24 borrow 3 → 2³ = 8 subnets, /27
  3. "I need X hosts": find the smallest h where 2h − 2 ≥ X. Prefix = 32 − h.
    50 hosts → 2⁵−2 = 30 ✗, 2⁶−2 = 62 ✓ → /26
  4. "I need N subnets": find the smallest n where 2n ≥ N. Add n to the prefix.
    5 subnets from /24 → 2²=4 ✗, 2³=8 ✓ → borrow 3 → /27
  5. Network increment = 256 − the interesting mask octet.
    255.255.255.240 → 256 − 240 = 16

Stretch mode (prefixes under /24)

Same steps, but the interesting octet moves left. Rule: every octet after the interesting one becomes 0 for the network and 255 for the broadcast.
